**결론: 범위를 "미리" 좁히지 말고, 넓게 허용한 뒤 제출 직전에 변경 한 덩어리마다 "요청의 어느 구절 때문인가"를 에이전트가 스스로 인용하게 하고, 인용 못 하는 변경은 자동으로 떼어내 '별도 제안 패치'로 보내는 것부터 해보세요. 막는 시점을 작업 전에서 작업 후로 옮기면 "좁히면 실패, 넓히면 오염" 양자택일이 사라집니다.**

> 가정: 에이전트의 시스템 프롬프트·훅·후처리 스크립트는 바꿀 수 있고, 모델 자체는 못 바꿉니다. 테스트/빌드가 어느 정도 있고, 결과는 git diff로 받습니다. 이미 해본 "수정 가능 범위 제한"은 후보에서 뺐습니다.

### ① 넓게 풀고, 제출 직전 '근거 인용 심사'로 걸러내기
- 뭘 하나: 수정 범위 제한을 없앤다. 대신 완료 시 에이전트가 diff를 변경 덩어리(hunk) 단위로 보며 "요청문 중 어느 구절이 이 변경을 요구했나"를 한 줄씩 인용하게 한다. 인용이 비거나 억지인 덩어리는 본 PR에서 빼고 `suggestions.patch`로 따로 저장한다.
- 왜 내 상황에 맞나: 필요한 수정은 어디든 할 수 있으니 실패율이 안 오르고, 엉뚱한 변경은 사람이 아니라 에이전트가 치운다. "건드리지 마라" 지시와 달리 작업 중 판단이 아니라 끝난 뒤 증거를 요구하는 점이 다르다.
- 안 통하는 조건: 에이전트가 모든 변경에 그럴듯한 근거를 지어내면 필터가 무력화된다(이때는 ②와 결합).
- 첫 실험: 담당자 1명, 과거에 오염이 있었던 요청 10건을 재실행 → 요청 무관 파일 변경 수가 기존 대비 절반 이하, 완수율은 유지되면 계속.

### ② 변경을 하나씩 되돌려보고 테스트가 그대로 통과하면 '불필요'로 자동 제거
- 뭘 하나: 에이전트 작업 후 스크립트가 각 덩어리를 하나씩 되돌린 채 빌드+관련 테스트를 돈다. 되돌려도 통과하면 그 변경은 요청 달성에 필요 없는 것이므로 PR에서 빼서 제안 패치로 옮긴다.
- 왜 내 상황에 맞나: 판단을 모델에 맡기지 않고 이미 있는 테스트를 "필요성 판정기"로 재활용한다. 흔한 "사후 테스트로 검증"은 합격/불합격만 보지만, 이건 변경 단위로 빼도 되는 것을 실험으로 찍어낸다.
- 안 통하는 조건: 테스트 커버리지가 낮으면 필요한 변경도 "빼도 통과"로 잘못 제거된다. 요청에 대한 테스트(또는 재현 스크립트)가 먼저 있어야 한다.
- 첫 실험: 1명, 테스트가 있는 모듈의 요청 5건에서 수동으로 덩어리 되돌리기 → 제거된 변경 중 사람이 봐도 불필요한 비율 80% 이상이면 자동화 착수.

### ③ 범위를 사람이 주지 않고, 에이전트가 먼저 '선언'하고 벗어날 때 비용을 내게 하기
- 뭘 하나: 에이전트가 수정 전에 읽기만으로 탐색해 "건드릴 파일 목록 + 이유"를 선언한다. 선언 안은 자유, 선언 밖 파일을 수정하려면 "범위 확장 요청(파일·이유)"을 로그에 남겨야 하며, 선언 파일에서 의존성으로 멀어질수록 더 긴 근거를 요구한다.
- 왜 내 상황에 맞나: 허용 목록처럼 벽을 세우지 않으니 필요한 수정이 막히지 않고, 벗어난 변경은 모두 로그에 이유와 함께 남아 리뷰가 그 부분에 집중된다. 경계를 사전에 사람이 정하지 않고 작업마다 에이전트가 만든다는 점이 다르다.
- 안 통하는 조건: 탐색 단계가 부실해 선언이 엉성하면 확장 요청이 쏟아져 로그가 의미를 잃는다.
- 첫 실험: 프롬프트만 바꿔 1주 운영 → 확장 요청 중 사람이 "정당"하다고 판정한 비율 70% 이상, 무관 파일 변경이 줄면 훅으로 강제.

### 와일드카드: 같은 요청을 2~3번 독립 실행해 '모두 겹치는 변경'만 통과
- 뭘 하나: 동일 요청을 에이전트 2~3개 인스턴스가 따로 수행하고, 전원이 건드린 파일/덩어리는 자동 통과, 한 인스턴스만 건드린 것은 "우연한 오염" 후보로 격리한다.
- 왜 내 상황에 맞나: 무엇이 필요한지 정의하지 않아도 "독립 시도 간 합의"가 필요성을 드러낸다. 위험: 비용 2~3배, 정당한 변경도 구현 방식이 갈리면 불일치로 걸러질 수 있다.
- 안 통하는 조건: 구현 자유도가 높은 요청(리팩토링 등)은 겹치는 부분이 거의 없다.
- 첫 실험: 버그 수정형 요청 5건을 2회씩 실행 → 양쪽 공통 파일만으로 테스트가 통과하는 비율 60% 이상이면 더 본다.
