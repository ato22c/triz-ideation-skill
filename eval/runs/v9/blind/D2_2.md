## 추천 3안 + 와일드카드

### 1. 내가 건 알림 — 알림 시각을 사용자가 정한다
- 뭘 하나: 콘텐츠·항목·할 일 화면마다 "내일 저녁에 다시 알려줘" 버튼을 둔다. 사용자가 누른 것만 그 시각에 알림으로 간다. 앱이 먼저 보내는 알림은 그대로 두거나 줄인다.
- 왜 뻔하지 않나: 흔한 답 "발송 시간·내용 맞춤화"는 여전히 앱이 고르고 보낸다. 이 안은 보내는 쪽이 사용자 본인이라 "원치 않는 알림"이 애초에 생기지 않는다.
- 가장 약한 고리: 버튼을 누르는 사용자가 소수면 재방문 총량이 안 는다. 눌러도 그 사람들이 원래 열성 사용자일 수 있다.
- 첫 실험: 최근 30일 내 알림을 받은 사용자 중 무작위 2,000명에게 버튼 노출, 다른 2,000명은 지금 방식 그대로, 2주 → 성공 = 이 버튼으로 간 알림의 열람률이 지금 일반 알림의 2배 이상이고, 처치군 전체의 주간 방문일이 대조군 대비 -3% 이내(줄지 않음). 해지율은 2주에 수십 명 수준이라 판정이 안 되므로 참고만 한다. / 비교 = 지금 방식 / 흐릴 요인: 버튼을 누른 사람만 비교하면 원래 열성 사용자 효과가 섞이므로 노출군 전체 대 대조군 전체로 비교.

### 2. 돌아오면 밀린 걸 한 화면에 — 알림 대신 방문의 이유를 키운다
- 뭘 하나: 알림은 지금의 절반으로 줄이고, 앱을 열면 첫 화면 맨 위에 "안 오신 동안 놓친 것 3가지" 카드를 보여준다. 알림은 "부르는 역할"만, 알맹이는 방문 뒤에 준다.
- 왜 뻔하지 않나: 흔한 답 "빈도 줄이기"는 재방문도 같이 줄어든다. 이 안은 알림이 줄어도 "가면 챙길 게 있다"는 기대를 키워서 방문 이유를 알림 밖에서 만든다.
- 가장 약한 고리: 카드 내용이 시시하면 알림이 줄어든 만큼 재방문만 빠진다. 앱에 "놓친 것"이라 부를 만한 변화가 없는 사용자(활동이 적은 사용자)에게는 안 통한다.
- 첫 실험: 5,000명(알림 절반 + 카드) 대 5,000명(지금 방식), 4주 → 성공 = 주간 재방문일이 대조군의 95% 이상이면서 알림 해지가 30% 이상 적다(대조군 해지가 4주에 150명 안팎이면 45명 이상 차이가 나야 우연과 구별된다). 카드는 개발 없이 하드코딩한 간이 목록으로 시작. / 비교 = 지금 방식 / 흐릴 요인: 4주 안에 낀 프로모션·명절.

### 3. 이미 보는 곳에 얹기 — 푸시 대신 캘린더에 소식을 넣는다
- 뭘 하나: 알림을 이미 끈 사용자에게 "주간 하이라이트·마감·예약"을 개인 캘린더 구독 링크(ICS 파일 주소)로 제공한다. 푸시가 아니라 사용자가 매일 여는 캘린더에 조용히 일정이 생긴다.
- 왜 뻔하지 않나: 흔한 답 "이메일·문자로 채널 바꾸기"는 또 하나의 수신함을 늘려 똑같이 스팸 취급된다. 이 안은 사용자가 스스로 구독하고 이미 매일 보는 화면에 얹는다.
- 가장 약한 고리: 캘린더를 안 쓰는 사용자가 많으면 구독 자체가 안 일어난다. 캘린더에 뜨는 일정이 너무 많아지면 거기서도 외면받는다.
- 첫 실험: 알림을 끈 사용자 600명 무작위, 300명에게 앱 내 배너로 구독 링크 안내(링크는 손으로 만든 정적 파일), 300명은 그대로, 3주 → 성공 = 안내받은 사람의 구독 전환 20% 이상이고 주간 방문자 비율이 대조군보다 8%p 이상 높다(300 대 300에서 8%p 차이면 우연을 벗어난다). / 비교 = 안내 없는 300명 / 흐릴 요인: 캘린더를 원래 많이 쓰는 직군·연령 편중.

### 와일드카드. 지인이 대신 부른다 — 앱이 아닌 사람이 부르는 알림
- 뭘 하나: 사람 간 연결(친구·팀·가족)이 있는 앱이면, 알림을 끈 사용자에게 활발한 지인이 "콕 찌르기/기다려요" 한 번을 보낼 수 있게 한다. 받는 쪽엔 앱 알림이 아니라 사람의 메시지로 보인다.
- 왜 뻔하지 않나: 흔한 답 "친구 활동 알림"은 앱이 보내는 알림 한 종류일 뿐이다. 이 안은 보내는 주체를 사람으로 바꿔 끄지 않는 이유를 만든다.
- 가장 약한 고리: 사람 간 연결이 없는 앱이면 성립하지 않는다. 남발되면 지인 스팸이 되어 관계가 상한다.
- 첫 실험: 알림을 끈 사용자 400명(콕 보내기 가능한 지인이 있는 사람만), 200명은 지인이 콕을 보낼 수 있게 하고 200명은 그대로, 2주 → 성공 = 콕을 받은 사람의 7일 내 방문률이 대조군보다 10%p 이상 높다. / 비교 = 지금 방식 / 흐릴 요인: 콕을 보내는 지인은 원래 자주 만나는 사이라 자기선택 편향이 큼 → 대조군도 "콕 가능했지만 안 보낸 쌍"으로 잡는다.

## 근거: 문제 재정의와 모순

**가정(되물을 수 없어 둔 것):**
- 앱 종류는 알 수 없어 일반 소비자 앱, 활성 사용자 수만 명 이상으로 가정했다.
- "알림을 늘리면 재방문이 는다"는 알림 덕분이라고 가정했지만 원래 열성 사용자에게 알림이 더 많이 간 결과일 수도 있다(상관과 인과 혼동). 틀리면 2안이 무너지고 알림을 줄여도 재방문이 안 떨어질 수 있다. 가장 싸게 확인하려면 알림 끈 사용자와 켠 사용자의 끈 이전 재방문 수준을 비교하면 된다.
- "해지는 원치 않는 알림 때문"이라고 가정했다. 틀리면(예: 알림 자체가 불편해 해지) 1안이 약해진다. 해지 사용자 10명 인터뷰나 설문 1문항으로 확인한다.
- 이미 해본 것은 알려지지 않아 흔한 답은 부록의 목록으로 잡았다.

**기능 문장:** 사용자가 앱이 가치 있는 순간에 스스로 돌아오게 하되(목적), 알림이 귀찮아서 끄지 않게 한다(불편). "왜?"를 두 번 올려 보면 재방문은 수단이고 목적은 가치를 받는 순간의 연결이라 이 문장으로 정했다.

**모순 쌍:**
- 기술적 모순(하나를 좋게 하면 다른 게 나빠짐): 알림을 늘리면 재방문은 오르지만 해지가 는다. 줄이면 반대다.
- 물리적 모순(같은 것이 서로 반대를 요구받음): 알림은 많아야 하고(재방문) 동시에 적어야 한다(해지 방지).
- 이상적 최종결과(IFR, 비용·장치 없이 목적이 저절로 이뤄진 모습): 사용자가 알림 없이도 가치 있는 순간에 스스로 앱을 연다. 이미 공짜로 있는 자원: 사용자가 앱에서 하는 행동 기록, 알림을 끈 사용자 기록, 사용자의 캘린더, 잠금·홈 화면, 지인 관계, 알림을 열지 않은 기록.

**추천안별 연결 (분리 = 반대 요구를 나눠 푸는 방식):**
- 1안: 조건 분리. 사용자가 요청한 알림은 많아도 되고 요청 안 한 알림은 0에 가깝게.
- 2안: 시간 분리. 알림 시점에는 적게, 방문 시점에는 풍성하게.
- 3안: 공간 분리. 푸시 채널에서는 0, 사용자가 이미 보는 표면에서만 노출.
- 와일드카드: 수준 분리(앱 전체 발송은 적게, 개인 간 신호는 많게). 다만 모순을 온전히 푸는 안은 아니고 앱 종류에 크게 의존해 와일드카드로 뒀다.

**발산 로그** (스윕: 5개 방향에서 각 2개, 끌리지 않는 것 우선):

- [사전 조치] 앱을 닫을 때 다음 방문 시각을 미리 예약 — 사용자 스스로 한 약속
- [주기적 작용] 매주 정해진 시각에 "이번 주 소식" 하나 — 예측 가능한 리듬(기다림 형성)
- [반대로 하기] 사용자가 자기에게 거는 알림 — 발신자 뒤집기
- [셀프서비스] 반응 없으면 자동으로 줄고 반응하면 늘어나는 알림 — 발송 조절의 변형(금지 1·2와 같음)
- [다른 채널로 대체] SKIP(스마트워치 진동 등은 강도·채널만 바꾸는 변형)
- [색·투명도 변화] 알림센터에 쌓지 않고 배지 점 하나만 — 강도 낮추기의 변형

- [극단화-크기·시간·비용 0/∞] 하루 100번 와도 안 끄는 알림은? 배달 진행처럼 내가 시작한 일의 결과 → 열린 건에만 알림. 알림 0이면? 돌아온 순간 요약. 알림이 도착 후 스스로 사라지면? → 유효기간 자동 회수
- [극단화-먼 분야 유추] 도서관 대출 예약 알림(내가 신청한 것만), 복약 앱(환자가 시각 정함), 철도 시간표(예측 가능한 리듬)
- [극단화-자원 없이 시작] 가장 쓸모없어 보이는 자원 = 알림을 끈 사용자 → 이들을 알림 없는 대조군으로 삼아 알림의 진짜 효과 측정
