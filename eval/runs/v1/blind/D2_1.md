# 푸시 알림 딜레마: 재방문 vs 알림 차단 (TRIZ 발상, 빠르게 모드)

**적용한 가정** (되물을 수 없어 세운 것)
- 앱 종류와 알림 종류(마케팅/서비스 혼합)는 모른다. 일반 소비자 앱으로 본다.
- "알림 off"는 OS 수준 차단이라 되돌리기 어렵고 그 사용자에게 다시 닿을 채널이 사라진다고 본다.
- 이미 해본 것은 뻔한 답(빈도 캡, 개인화 등)으로 가정한다. 해봤다면 3번 금지 목록이 그대로 적용된다.
- 모드는 지정이 없어 기본값인 빠르게(5개 방향 x 각 2개 = 10개 원리, 최소 15개 아이디어)로 진행했다.

## 1. 추천 3안 + 와일드카드

**안 1. 강등 사다리 + 알림 없는 재방문 통로** (실현성 축)
- 요약: 사용자가 알림을 끄려는 신호(반복 무시·스와이프 삭제·설정 진입)가 보이면 "완전 끄기"와 "지금 방식 유지" 사이에 단계를 둔다. 예: 하루 요약 1개 / 중요한 것만 / 주 1회. 동시에 OS 알림이 이미 꺼진 사용자에게는 위젯·잠금화면 상태 카드·앱 아이콘 배지처럼 푸시가 아닌 수동 노출 면을 준다.
- 왜 뻔하지 않은가: 빈도를 조절하는 게 아니라 "끄는 행동"을 이탈이 아닌 다운그레이드 선택으로 바꾼다. 알림 off를 실패가 아니라 신호로 쓴다. [22 전화위복] [31 다공질]
- 첫 실험: 앱 안에서 "이 알림 그만 받기"를 누르거나 연속 N회 무시한 사용자에게만 2단 선택지(요약/중요만/끄기)를 띄운다. 2주간 OS 차단 전환율과 7일 재방문율을 비교한다.

**안 2. 사용자가 직접 쓰는 알림 예산** (이상성 축)
- 요약: 사용자에게 하루(또는 주) 알림 토큰 N개를 준다. 사용자가 "이 종류/이 상황에는 나를 불러도 좋다"에 토큰을 배분한다. 앱은 토큰을 다 쓰면 못 보낸다. 앱이 정한 빈도 캡이 아니라 사용자가 정한 예산이라는 점이 다르다.
- 왜 뻔하지 않은가: 빈도 결정권을 시스템에서 사용자에게 넘긴다. 예산이 있으면 남은 알림 하나하나가 "내가 허락한 것"이 되어 차단 동기가 줄어든다. [25 셀프서비스]
- 첫 실험: 코드 없이 시작한다. 알림 설정 화면에 "하루 몇 번까지 괜찮으세요? 1 / 3 / 5" 선택기만 넣고, 선택값대로 발송량을 제한해 선택한 그룹과 무선택 그룹의 차단율·재방문율을 비교한다.

**안 3. 스스로 사라지는 알림 + 무반응 시 침묵-부활** (참신도 축)
- 요약: 알림에 수명을 준다. 유효 시간이 지나면 알림센터에서 자동 철회한다(쌓이지 않음). 무반응이 이어지면 그 사용자에게는 완전 침묵으로 들어가고, 침묵 중 "정말 가치 큰 사건"이 생겼을 때만 부활한다. 부활 기준은 그 사용자의 과거 반응 데이터로 정한다.
- 왜 뻔하지 않은가: 빈도를 줄이는 것이 아니라 알림의 "존재 시간"과 "침묵 상태"를 설계 대상으로 삼는다. 알림이 쌓여 짜증을 만드는 경로를 끊는다. [34 폐기와 재생] [18 진동] [37 열팽창]
- 첫 실험: 만료 시간(TTL)이 지난 프로모션 알림 자동 철회만 먼저 적용한다. 철회 그룹과 유지 그룹의 알림 차단율을 비교한다.

**와일드카드. 친구를 매개로 한 알림** (사람 채널)
- 요약: 앱이 사용자를 부르는 대신 아는 사람이 부르게 한다. 예: "○○님이 기다려요" 또는 상대가 보낸 짧은 콕. 사용자는 앱의 알림은 꺼도 지인의 호출은 켜 두는 경우가 많다. 복약 순응 프로그램에서 보호자가 알림을 받는 구조에서 가져왔다.
- 왜 뻔하지 않은가: 알림의 발신자를 앱에서 사람으로 바꾼다. 시스템의 빈도 문제가 개인 간 관계 문제로 바뀐다. [24 매개체] (먼 분야 유추)
- 첫 실험: 기존 공유/초대 기능이 있으면 초대 수신자에게 "친구가 콕 찔렀어요"라는 알림 1종만 추가하고, 일반 푸시 대비 열람률과 차단율을 본다. 소셜 기능이 없으면 이 안은 보류한다.

## 2. 문제 재정의와 모순

**기능 문장:** 사용자가 "지금 이 앱을 볼 가치가 있다"는 걸 방해받는 느낌 없이 알게 한다.

- "왜?" 올리기: 왜 푸시를 보내나 -> 다시 방문하게 하려고 -> 왜 방문시키나 -> 사용자가 앱에서 가치를 얻는 순간을 놓치지 않게 하려고. 더 넓은 목표는 "가치 있는 순간을 사용자가 놓치지 않게 한다"이고, 푸시는 그 수단 중 하나일 뿐이다. 이 문장으로 갈아탄다.

**기술적 모순**
- 알림 빈도(도달)를 올리면 재방문은 오르지만 차단(채널 상실)도 오른다.
- 빈도를 내리면 차단은 줄지만 재방문이 떨어진다.

**물리적 모순:** 알림은 많아야 하고(도달·기억) 동시에 적어야 한다(피로·차단).
- 분리 4종 적용: 시간(가치 있는 순간에만 많이) / 조건(반응하는 사람에게만) / 수준(전체 알림은 적게, 개별 사용자에게는 원하는 만큼) / 공간(푸시가 아닌 다른 노출 면).

**IFR:** 사용자가 알림도 방해도 없이, 가치 있는 순간에 저절로 앱을 떠올리고 온다.

**공짜 자원 (5개 이상)**
1. 사람: 친구·가족·같은 그룹 사용자
2. 시간: 사용자가 이미 폰을 여는 습관 시점(잠금 해제, 캘린더 확인)
3. 데이터: 알림 열람/무시/스와이프 로그, 설정 진입 기록
4. 물건/공간: 잠금화면, 위젯, 앱 아이콘 배지, 알림센터의 빈 자리
5. 기존 기능: "끄기" 버튼 자체, 알림 설정 화면, 앱을 열었을 때의 첫 화면

## 6. 다음 행동

1. 먼저 안 1의 첫 실험을 한다. 이유: 가장 싸고 빠르며, 차단으로 잃는 채널을 되찾는 것은 안 2, 3의 효과도 키운다.
2. 안 1 실험과 병행해서, 알림 차단(OS 수준 off)한 사용자 비율과 그 사용자들의 재방문 경로를 현재 데이터로 확인한다. 이 숫자에 따라 "알림 없는 재방문 통로"의 우선순위가 정해진다.
3. 결과가 빈약하면 깊게 모드(40개 원리 전부, 최소 30개)로 올려 볼지 판단한다. 지금은 한 줄 제안: 알림 종류(마케팅/서비스)와 앱 종류를 알려주시면 깊게 모드를 더 정확하게 돌릴 수 있다.
4. 소셜/공유 기능이 있는지 확인한 뒤, 있으면 와일드카드를 안 1 다음 실험으로 올린다.
