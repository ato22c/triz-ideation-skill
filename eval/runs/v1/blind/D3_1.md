# 주간 회의 1시간 반 -> 지루하지 않고 중복도 없게 (TRIZ 발상, 빠르게 모드)

**가정 (되물을 수 없어 적고 진행):** 지식노동/개발형 팀이고 이슈 보드나 메신저를 이미 쓴다. 회의는 유지하되 길이와 형식은 바꿀 수 있다. 해본 것은 알 수 없어 "흔한 시도"는 금지 목록에 넣었다. 모드는 지정이 없어 기본값 "빠르게"(5개 방향 x 2개 원리, 아이디어 15개 이상)로 했다.

## 1. 추천 3안 + 와일드카드

**안 1. "변한 것만 논의" 회의 + 자동 요약판** [36 상전이, 26 복제, 6 범용성]
- 요약: 회의에서 전원이 돌아가며 근황을 말하지 않는다. 지난주 이후 상태가 바뀐 항목만 화면에 띄워 그것만 논의하고, 변화 없는 항목은 침묵 통과한다. 화면은 티켓/커밋 로그에서 자동으로 만든다.
- 왜 뻔하지 않나: "보고를 줄이자"가 아니라 정보 공유를 회의에서 로그로 옮기고, 회의는 변화와 충돌만 다루게 한다. 사람이 하던 요약을 없앤다.
- 첫 실험: 다음 회의 전에 보드에서 "최근 7일 상태 변경" 필터 화면 하나를 만들고 그것만 논의해 본다. 걸린 시간과 "몰랐던 겹침 발견 건수"를 적는다.

**안 2. 일회용 착수 깃발 + 겹침 빨간불** [27 값싼 일회용, 32 색 변화]
- 요약: 새 작업을 시작할 때 채널에 "[동사+대상] 담당 OOO" 한 줄을 남긴다(깃발). 완료하면 자동으로 사라진다. 제목이 비슷한 깃발이 두 개면 붉게 표시한다.
- 왜 뻔하지 않나: 중복 방지를 "주 1회 알려주기"가 아니라 "착수 순간의 일회성 선점"으로 바꾼다. 회의 없이도 겹침이 시작 전에 걸러진다.
- 첫 실험: 이번 주 전원이 착수 시 한 줄만 남긴다. 주말에 최근 4주 대비 중복 작업 건수를 비교한다.

**안 3. 교차 참여 시간표 (구멍 뚫린 회의)** [31 다공질, 40 복합 재료]
- 요약: 90분 단일 덩어리를 "5분 전체 공유 + 소그룹 병렬 20분 x 2 + 10분 결정"으로 재조합한다. 안건마다 필요한 사람만 표시해 나머지는 그 시간에 자유롭게 빠진다.
- 왜 뻔하지 않나: 단축이 아니라, 같은 90분 안에서 한 사람이 실제로 붙잡히는 시간을 줄인다. 회의는 유지된다.
- 첫 실험: 다음 회의 안건을 사전에 항목별로 "필요한 사람"과 함께 적고, 해당 없는 사람은 자리를 비워도 되게 한 번만 시범 운영한다.

**와일드카드. 상시 열린 팀 라운지** [STC 시간 무한대]
- 요약: 회의를 "주 1회 90분"이 아니라 상시 열린 음성방으로 바꾼다. 필요한 사람이 드나들고, 모이면 그 자리가 곧 회의다. 정보는 흐르고 정해진 모임은 결정 때만 생긴다.
- 왜 뻔하지 않나: 회의를 없애지 못한다는 제약을 "회의를 없앨 필요 없이 시간을 무한대로 늘린다"로 뒤집는다.
- 첫 실험: 2주간 화/목 오후 1시간만 열린 음성방을 열고, 자발 입장 인원과 중복 발견 건수를 본다.

## 2. 문제 재정의와 모순

- **기능 문장:** 팀원 10명이 서로의 작업을 알아 중복을 피하되, 전원이 오래 붙잡히는 동기 시간은 최소화한다.
- **왜? 2번 올리기:** 왜 서로 알아야 하나 -> 중복 방지 -> 왜 중복이 문제인가 -> 팀 시간이 낭비돼서. 넓힌 목표는 "팀의 시간이 낭비 없이 한 방향으로 쓰인다"이다. 지루한 회의도 낭비이므로 이 문장으로 확장해 풀어도 같은 방향이다.
- **기술적 모순:** 정보 공유(정렬)를 높이면 -> 소요 시간과 지루함이 늘어난다. 반대로 시간을 줄이면 -> 중복이 늘어난다.
- **물리적 모순:** 회의는 존재해야 한다(정보 교환, 중복 방지). 동시에 존재하면 안 된다(길고 지루하다).
  - 시간 분리: 정보는 상시 비동기로, 모임은 결정/충돌 때만.
  - 수준 분리: 전체는 짧게, 세부는 관련자 소그룹에서.
  - 조건 분리: 겹칠 위험이 있을 때만 대화.
  - 공간 분리: 로그/보드라는 별도 공간이 정보를 나른다.
- **IFR:** 각자의 작업 상태가 회의 없이 저절로 모두에게 보이고, 사람이 모이는 시간은 사람만 할 수 있는 결정과 충돌 해결에만 쓰인다.
- **자원(공짜로 있는 것):** 이슈 티켓/커밋/PR 로그, 캘린더, 메신저 활동 기록, 회의 시작 전 대기 5분, 회의록 자체, 청중이 남는 주의력, 이미 쓰는 도구의 상태 필드, 벽/화이트보드.

## 3. 금지 목록 (뻔한 답)

1. 사전 안건 공유
2. 회의를 30~45분으로 단축
3. 매일 15분 스탠드업으로 대체
4. 사전에 상태를 문서로 써서 읽고 오기
5. 타이머/엄격한 진행자
6. 슬랙에 주간 업데이트 스레드
7. 칸반/스프린트 보드 도입
8. 격주 회의로 빈도 줄이기

이와 같은 메커니즘은 참신한 아이디어로 치지 않았다.

## 4. 발산 로그

빠르게 모드 스윕 (끌리지 않는 것부터): A(31, 40), B(6, 33), C(18, 21), D(26, 27), E(32, 36).

1. [31 다공질] 안건별 입퇴장 시간표. 자기 항목이 아닌 구간은 빠진다.
2. [31 다공질] 회의 중 빈틈에 "침묵 읽기 10분"을 채워 말하기 대신 읽기로 정보를 전달한다.
3. [40 복합 재료] 90분 균질 -> 5분 전체 + 소그룹 병렬 + 10분 결정의 이질 조합.
4. [40 복합 재료] 참여 방식 혼합: 발표자 / 질문 전담 / 기록 전담 역할을 매주 섞는다.
5. [6 범용성] 이슈 보드 하나가 상태 공유, 중복 감지, 결정 로그를 겸해 별도 보고를 없앤다.
6. [6 범용성] 진행자가 겸하던 서기/타임키퍼 역할을 도구가 대신한다.
7. [33 동질성] 모든 작업을 "동사+대상+상태" 한 줄 카드로 통일해 겹침을 눈으로 스캔한다. (병원 인수인계의 정형 양식과 같은 구조)
8. [33 동질성] 전원 같은 30초 포맷으로만 말한다.
9. [18 진동] 진행자와 발표 순서를 매주 무작위로 뒤섞어 굳은 분위기를 깬다.
10. [21 서두르기] 상태 보고 구간만 극속으로 통과한다(1인 60초 초과 시 다음 사람).
11. [26 복제] 각자 60초 사전 녹음/녹화를 미리 듣고 오게 하고, 회의는 질문만 한다.
12. [26 복제] 로그(커밋/티켓)에서 자동 생성한 "지난주 팀 복제본" 요약을 회의 자료로 쓴다.
13. [27 값싼 일회용] 착수 깃발. 시작 시 한 줄 선언, 완료 시 소멸.
14. [27 값싼 일회용] 겹침이 의심될 때만 필요한 2~3명이 5분 즉석 콜을 열었다 닫는다.
15. [32 색·투명도] 제목이 유사한 깃발은 붉게 표시한다.
16. [32 색·투명도] 논의할 필요 없는 항목은 회색 처리해 회의에서 건너뛴다.
17. [36 상전이] 상태가 전환된 항목만 논의한다.
18. [STC 시간 무한대] 상시 열린 음성 라운지.
19. [STC 크기 0] 회의 참석자를 1명으로: 로테이션 "중계자"가 모아서 전달한다.
20. [STC 비용 무한대] 주 1시간 로테이션 "편집장"이 한 장짜리 브리프를 작성한다.
21. [STC 시간 0] 회의 없이 착수 전 선점 선언을 필수로 한다. (13의 변형이라 1개로 계산)
22. [거꾸로 하기: 일부러 악화 -> 전원이 모든 항목을 다 듣게 한다] 뒤집으면 관련자만 듣는다. (1의 변형)
23. [먼 분야 유추: 개미 페로몬(스티그머지)] 작업 흔적(티켓 이동, 커밋)이 곧 통신이 되는 "팀 작업 지도" 대시보드.
24. [먼 분야 유추: 항공관제] 각자 "담당 구역"을 표시하고, 남의 구역에 들어갈 때만 알림/교신한다.
25. [9 windows 상위 시스템 칸] 주 초에 작업 소유권을 미리 분할해 중복이 애초에 생기지 않게 한다. (원리 1 분할 계열)

서로 다른 메커니즘 기준 약 22개(21, 22는 변형이라 제외). SKIP 없음.

## 5. 다리 놓기 (가장 황당한 3개 -> 현실 버전)

1. **상시 열린 음성 라운지(18)** -> 핵심 메커니즘: "모임 시간을 정하지 않고, 정보가 흐르는 채널을 상시 열어 둔다". 현실 버전: 주 2회 1시간만 오픈하고 결정은 별도 30분으로 고정.
2. **참석자 1명 중계자(19)** -> 핵심: "정보 전달자와 결정자를 분리한다". 현실 버전: 로테이션 중계자가 사전 브리프를 작성해 회의는 질문과 결정만 한다(20과 결합).
3. **작업 흔적이 곧 통신(23)** -> 핵심: "말하지 않아도 환경에 남은 흔적으로 조정된다". 현실 버전: 안 1의 자동 요약판과 안 2의 깃발로 구현.

## 6. 평가표 (1~5, 자기 점수는 박하게)

| 후보 | 참신도 | 이상성 | 실현성 | 비고 |
|---|---|---|---|---|
| 안 1 변한 것만 논의 + 자동 요약판 | 3 | 5 | 4 | 이상성 최고 |
| 안 2 착수 깃발 + 겹침 빨간불 | 4 | 4 | 4 | 참신도 최고 (실전 후보 중) |
| 안 3 교차 참여 시간표 | 3 | 3 | 5 | 내일 시작 가능 |

## 7. 다음 행동

1. 이번 주 안에 안 3(시간표)을 한 번만 시범 운영하고, 동시에 안 2(깃발)를 켠다. 둘 다 준비물이 거의 없다.
2. 다음 회의 전에 안 1의 "최근 7일 상태 변경" 화면을 만들어 본다. 그 뒤 회의 시간과 발견한 겹침 수를 기록한다.
3. 4주 뒤 중복 작업 건수와 회의 시간을 비교한다. 개선이 없으면 "깊게" 모드(40개 원리 전체, 30개 아이디어)로 올리자. 특히 중복의 진짜 원인이 정보 부족인지 업무 배분 구조인지를 먼저 분리해 볼 가치가 있다(9 windows 상위 시스템 칸의 25번 아이디어).
4. 지금 결과가 빈약하다고 느끼면 팀 규모/도구/이미 해본 것을 알려 주면 깊게 모드로 다시 돌린다.
